---
title: GitHub integration setup
description: Set up the Faster Fixes GitHub integration to automatically create GitHub issues from feedback and sync status bidirectionally.
---

Faster Fixes creates a GitHub issue for each new feedback and syncs status between the dashboard and GitHub. For a product overview, see the [GitHub integration overview](/integrations/github).

## Setup

1. Go to **[Application Settings](/integrations) → Integrations** from the sidebar
2. Install the Faster Fixes GitHub App
3. Select which repositories to grant access to
4. In **[Project Settings](/settings) → GitHub**, link your project to a repository

## Auto-create issues

With auto-create on, the default, each new feedback creates an issue in the linked repository. The issue includes:

- Feedback comment
- Page URL
- DOM selector
- Link to play the [Recording](/docs/widget/recording) and its duration, when the feedback has one
- Browser info
- Link to the screenshot
- Console logs and network requests, in a collapsible section

## Recording

The **Recording** line links to the player in the dashboard. The link requires a Faster Fixes login, so an issue in a public repository exposes nothing of the Recording.

With a Recording, the collapsed **Diagnostics** section becomes a collapsed **Timeline**: the Reviewer's steps, console logs and network requests on one clock, ending with the element selection. A timeline too long for the issue drops its earliest entries and states how many. If the Recording cannot be read, the issue shows Diagnostics instead.

An automatic issue waits up to 30 seconds for the Recording to upload. A manual issue is created at once.

An issue is written once. A Recording that arrives later is not added, and removing a Recording in the dashboard leaves the timeline already written in the issue.

## Default labels

Issues are tagged `faster-fixes` by default. Change the labels in the GitHub link settings.

## Bidirectional status sync

| Action                                                  | Result                            |
| ------------------------------------------------------- | --------------------------------- |
| Feedback marked **resolved** or **closed** in dashboard | GitHub issue is closed            |
| Feedback marked **new** or **in_progress** in dashboard | GitHub issue is reopened          |
| GitHub issue **closed**                                 | Feedback status updated to closed |
| GitHub issue **reopened**                               | Feedback status updated to new    |

## Manual issue creation

Create an issue from any feedback in the Task board with the **Create Issue** action.

## Unlinking

Unlink a repository from **[Project Settings](/settings) → GitHub**. Existing issue links are kept, and sync stops.
