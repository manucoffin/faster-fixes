---
title: Jira integration setup
description: Set up the Faster Fixes Jira integration to automatically create Jira issues from feedback and sync status bidirectionally.
---

Faster Fixes creates a Jira Cloud issue for each new feedback and syncs status between the dashboard and Jira. Jira Server and Data Center are not supported.

The Jira integration is available on paid plans.

## Setup

1. Go to **[Application Settings](/integrations) → Integrations** from the sidebar
2. Click **Connect to Jira** and authorize the Faster Fixes app on your Atlassian account
3. If your account has access to several Jira sites, pick the one to connect
4. In **[Project Settings](/settings) → Jira**, link your project to a Jira project and issue type

Connecting requires the owner or admin role. One Jira site is connected per organization, and each project links to one Jira project within that site.

Authorize with a service account rather than a personal one. Issues are attributed to the authorizing user, and the connection breaks if they lose Jira access or leave the company.

## Project settings

| Setting            | Description                                                                |
| ------------------ | -------------------------------------------------------------------------- |
| **Jira project**   | The Jira project that receives new issues                                  |
| **Issue type**     | Pre-selected to Bug when available                                         |
| **Default labels** | Applied to every created issue, `faster-fixes` by default. No spaces.      |
| **Auto-create**    | Turns automatic issue creation on or off without unlinking. On by default. |

Faster Fixes fills only the project, issue type, summary and description. If the issue type requires any other field, linking is blocked and lists the fields at fault: make them optional in Jira or pick another issue type. Changing the Jira project or issue type runs this check again. If a required field is added after linking, issue creation fails and the link is flagged in project settings.

## Issues

With auto-create on, each new feedback creates an issue in the linked Jira project. To create one manually, including with auto-create off, use the **Create Jira issue** action in the Trackers section of the feedback. The Trackers section then shows the issue key and a status dot linking to Jira.

An issue contains:

- Feedback comment
- Page URL
- DOM selector
- Link to play the [Recording](/docs/widget/recording) and its duration, when the feedback has one
- Link to the screenshot
- Browser info and the reviewer's name, collapsed
- Custom metadata, when the widget sends it, collapsed
- Console logs and network requests in a collapsed **Diagnostics** section
- Link to the feedback in the dashboard

When the feedback has a Recording, **Diagnostics** is replaced by a collapsed **Timeline** that lists the reviewer's steps, console logs and network requests on one clock. When the timeline is too long, its earliest entries are left out and the Timeline says how many. If the Recording cannot be read, the issue shows Diagnostics instead. The **Play in Faster Fixes** link requires a Faster Fixes login.

An automatic issue waits up to 30 seconds for the Recording to upload, and a manual issue is created at once. An issue is never rewritten: a Recording that arrives later is not added, and removing a Recording in the dashboard leaves the Timeline in the issue.

## Status sync

Statuses map by Jira status category (To Do, In Progress, Done), not by name, so custom and renamed workflow statuses work without configuration.

| Change                                          | Result                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| Feedback marked **resolved** or **closed**      | Issue transitions to a Done-category status                         |
| Feedback reopened to **new** or **in progress** | Issue transitions out of Done, to In Progress where available       |
| Issue moved to a **Done**-category status       | Feedback is resolved                                                |
| Issue moved to **To Do** or **In Progress**     | Feedback is set to **in progress**, never back to **new**           |
| Issue deleted in Jira                           | Issue is detached. The feedback is unchanged and can get a new one. |

Only crossing the Done boundary moves the issue: moving a feedback between **new** and **in progress** leaves it where it is. Where a transition accepts a resolution, resolved sets Done and closed sets Won't Do. If the workflow has no transition into the target category, the change is skipped.

## Unlink and disconnect

Unlink a Jira project from **[Project Settings](/settings) → Jira**, including on the free plan. Its issues stay in Jira and stop syncing.

Disconnecting from **[Application Settings](/integrations) → Integrations** unlinks every project and leaves existing issues in Jira. Disconnecting is owner-only. Atlassian has no API to revoke a grant, so also remove Faster Fixes from your Atlassian account's connected apps.
