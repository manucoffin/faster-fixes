---
title: Jira integration setup
description: Set up the Faster Fixes Jira integration to automatically create Jira issues from feedback and sync status bidirectionally.
---

Faster Fixes integrates with Jira Cloud to automatically create issues when new feedback is submitted and sync status changes between the dashboard and Jira. The integration runs alongside GitHub and Linear: a feedback can mirror to all three at once, and status changes propagate to each independently.

Jira Server and Data Center are not supported.

The Jira integration is available on paid plans.

## Setup

1. Go to **[Application Settings](/integrations) → Integrations** from the sidebar
2. Click **Connect to Jira** and authorize the Faster Fixes app on your Atlassian account
3. If your account has access to several Jira sites, pick the one to connect
4. In **[Project Settings](/settings) → Jira**, link your project to a Jira project and issue type

Connecting requires the owner or admin role. One Jira site is connected per organization; each project then links to a single Jira project within that site.

Authorize with a service account rather than a personal one. Jira's OAuth grant is bound to the authorizing user, so issues are attributed to that account and the connection breaks if they lose Jira access or leave the company.

## Auto-create issues

When enabled (on by default), new feedback automatically creates an issue in the linked Jira project.

## Defaults per project

Each project link controls how new issues are created:

| Setting            | Description                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------- |
| **Jira project**   | The Jira project that receives new issues                                                   |
| **Issue type**     | The issue type created, pre-selected to Bug when available                                  |
| **Default labels** | Labels applied to every created issue, defaulting to `faster-fixes`. Cannot contain spaces. |
| **Auto-create**    | Toggle automatic issue creation off without unlinking                                       |

### Required fields

Faster Fixes fills only the project, issue type, summary, and description. If the Jira project and issue type you pick require any other field, linking is blocked with the list of fields at fault. Make those fields optional in Jira, or choose an issue type that does not require them.

If a required field is added after linking, issue creation starts failing and the link is flagged in project settings.

## Bidirectional status sync

Status changes propagate in both directions. Mapping is by Jira's status **category**, To Do, In Progress, Done, not by status name, so custom and renamed workflow statuses still work without configuration.

| Action                                                       | Result                                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------------ |
| Feedback marked **resolved** or **closed** in dashboard      | Jira issue transitions to a Done-category status                   |
| Feedback reopened to **new** or **in progress** in dashboard | Jira issue transitions out of Done, to In Progress where available |
| Jira issue moved to a **Done**-category status               | Feedback status updated to resolved                                |
| Jira issue moved to **To Do** or **In Progress**             | Feedback status updated to in progress                             |

Two behaviors are worth knowing:

- Only crossing the Done boundary triggers a transition. Moving a feedback between **new** and **in progress** leaves the Jira issue where it is, so the integration does not fight your team's board.
- Reopening from Jira sets the feedback to **in progress**, never back to **new**. Feedback that has already been triaged does not reappear as untriaged.

Where a transition accepts a resolution, resolved sets Done and closed sets Won't Do. If a workflow offers no transition into the target category, the change is skipped and logged rather than treated as an error.

## Manual issue creation

You can create a Jira issue manually from any feedback item in the Inbox using the **Create Jira issue** action in the Trackers section. This works even when auto-create is off. Once an issue exists, the Trackers section shows its key and a status dot linking to Jira.

## Changing the Jira project or issue type

Switching either re-runs the link, including the required-fields check. Auto-create and labels can be edited in place.

## Issues deleted in Jira

Deleting a mirrored issue in Jira detaches it from the feedback and leaves the feedback untouched. You can export it to Jira again afterwards.

## Unlinking

You can unlink a Jira project from **[Project Settings](/settings) → Jira** at any time. Existing issue links are preserved but sync stops. Unlinking stays available on the free plan so a downgrade never traps you.

## Disconnecting

Disconnecting from **[Application Settings](/integrations) → Integrations** removes the Jira site and cascades all project links. Existing Jira issues are not deleted; they simply stop syncing. Disconnecting is owner-only.

Atlassian provides no API to revoke a grant, so also remove Faster Fixes from your Atlassian account's connected apps to fully revoke access.
