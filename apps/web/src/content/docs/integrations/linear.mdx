---
title: Linear integration setup
description: Set up the Faster Fixes Linear integration to automatically create Linear issues from feedback and sync status bidirectionally.
---

Faster Fixes creates a Linear issue for each new feedback and syncs status between the dashboard and Linear in both directions. For a product overview, see the [Linear integration overview](/integrations/linear).

## Setup

1. Go to **[Application Settings](/integrations) → Integrations** from the sidebar
2. Click **Connect Linear** and authorize the Faster Fixes OAuth app on your workspace
3. In **[Project Settings](/settings) → Linear**, link your project to a team
4. Pick the default state, labels, and priority for new issues

The OAuth grant is workspace-wide. Each project links to a single team within that workspace.

## Project defaults

| Setting              | Description                                           |
| -------------------- | ----------------------------------------------------- |
| **Team**             | The Linear team that receives new issues              |
| **Default state**    | Workflow state used for new feedback (typically Todo) |
| **Default labels**   | Labels applied to every created issue                 |
| **Default priority** | None, Urgent, High, Medium, or Low                    |
| **Auto-create**      | Toggle automatic issue creation off without unlinking |

Switching to a different team requires re-picking the default state and labels in the same step.

If a saved state or label is deleted in Linear, Faster Fixes falls back to a state of the matching type and shows a banner in project settings prompting you to re-pick.

## Issues

With auto-create on, the default, each new feedback creates an issue in the linked team. To create one manually, use the **Create Linear issue** action on a feedback in the Task board. A manual issue is created in the state matching the feedback's current status, so an already-resolved feedback opens a `completed`-type issue.

An issue contains:

- Feedback comment
- Page URL
- The selected element: its component path, source file, DOM selector and click position, or an [area](#area-feedback) and the element it sits inside
- Link to play the [Recording](/docs/widget/recording) and its duration, when the feedback has one
- Browser info
- Link to the screenshot
- Console logs and network requests, in a collapsed **Diagnostics** section

Issues are created as the Faster Fixes app, not as the member who installed the integration.

When the feedback has a Recording, **Diagnostics** is replaced by a collapsed **Timeline** section listing the Reviewer's steps, console logs and network requests on one clock. When the timeline is too long, its earliest entries are left out and the Timeline says how many. If the Recording cannot be read, the issue shows Diagnostics instead. The **Play in Faster Fixes** link requires a Faster Fixes login.

An automatic issue waits up to 30 seconds for the Recording to upload, a manual issue is created at once. An issue is never rewritten: a Recording that arrives later is not added, and removing a Recording in the dashboard leaves the timeline already in the issue.

## Area feedback

When the reviewer drags to select an area instead of clicking an element, the issue shows an **Area** line with the area's size and position in the viewport, then an **Inside** line with the component path, source file and DOM selector of the element that contains the whole area. That element is context, not what was selected, and the issue has no click coordinates. The screenshot is the full viewport, without the area drawn on it.

## Status sync

Statuses map to Linear's workflow state **type**, not its name, so renamed or custom states work.

| Feedback status       | Linear state type                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| **New**               | The project's default state. An issue moved to Triage, Backlog or Todo sets the feedback to New. |
| **In progress**       | `started`                                                                                        |
| **Resolved**          | `completed`                                                                                      |
| **Closed** (Archived) | `canceled`                                                                                       |

Changes apply in both directions. A feedback can be linked to a GitHub issue and a Linear issue at the same time, and status changes propagate to both.

## Unlink and disconnect

Unlink a team from **[Project Settings](/settings) → Linear** at any time. Existing issue links are kept but sync stops.

Disconnecting from **[Application Settings](/integrations) → Integrations** removes the OAuth grant and unlinks every project. Existing Linear issues are not deleted and stop syncing.
