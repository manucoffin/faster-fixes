---
title: Agent API
description: REST API for AI agents to list and read feedback, list videos and update status.
---

The Agent API is designed for programmatic access by AI coding agents. It's the same API used by the [MCP server](/docs/mcp/setup).

**Base URL:** `https://www.faster-fixes.com/api/v1/agent`

## Authentication

All requests require a Bearer token in the `Authorization` header:

```
Authorization: Bearer ff_agent_xxx
```

Create agent tokens in [Integrations](https://faster-fixes.com/integrations). See [Agent Tokens](/docs/concepts/agent-tokens) for details.

---

## List feedbacks

```
GET /feedbacks?project=proj_xxx
```

### Query parameters

| Parameter  | Type     | Required | Description                                          |
| ---------- | -------- | -------- | ---------------------------------------------------- |
| `project`  | `string` | Yes      | Project ID (prefix: `proj_`)                         |
| `status`   | `string` | No       | Filter: `new`, `in_progress`, `resolved`, `closed`   |
| `page_url` | `string` | No       | Filter by page URL                                   |
| `video`    | `string` | No       | Filter by Video ID (see [List videos](#list-videos)) |
| `format`   | `string` | No       | `json` (default) or `markdown`                       |

`video` and `page_url` are mutually exclusive. Sending both returns `400` with the code `VALIDATION_ERROR`. A `video` that does not belong to the Project returns `404` with `Video not found`.

### JSON response

```json
      "id": "uuid",

      "clickX": 450,
      "clickY": 320,
      "viewportWidth": 1920,
      "viewportHeight": 1080,
      "browserName": "Chrome",
      "browserVersion": "120",
      "os": "macOS",
      "screenshotUrl": "https://...",
      "metadata": {},
      "diagnosticTrail": {
        "console": [
          {
            "level": "error",
            "message": "Uncaught TypeError: x is undefined",
            "timestamp": 1736937000000
          }
        ],
        "network": [
          {
            "method": "GET",
            "url": "https://api.myapp.com/user",
            "status": 500,

          }

```

`customMetadata` holds the key/value pairs your site attached with the widget's `customMetadata` option, or `null` when it attached none.

`screenshotUrl` is a signed URL that expires one hour after the response. Request the listing again to get a fresh one.

`recording` summarizes the Feedback's [Recording](/docs/widget/recording), or is `null` when it has none:

| Field        | Type             | Description                                                                                         |
| ------------ | ---------------- | --------------------------------------------------------------------------------------------------- |
| `durationMs` | `number`         | Duration of the Recording in milliseconds                                                           |
| `stepCount`  | `number \| null` | Number of steps, or `null` until a request for the [single Feedback](#get-a-feedback) has read them |

The listing never carries the timeline or a link to the Recording file. [Get a feedback](#get-a-feedback) returns both.

### Video feedback

Every item has the same keys, whether it was left on a page or on a Video. Without a filter, the listing mixes both, and `videoId` lets you group items by Video.

| Field                                                             | Page item      | Video item                   |
| ----------------------------------------------------------------- | -------------- | ---------------------------- |
| `videoId`                                                         | `null`         | The Video ID                 |
| `selection`                                                       | `null`         | The marked time and position |
| `pageUrl`                                                         | The page URL   | `null`                       |
| `selector`, `clickX`, `clickY`, `viewportWidth`, `viewportHeight` | When captured  | `null` unless captured       |
| `metadata`, `diagnosticTrail`, `customMetadata`                   | When captured  | `null`                       |
| `screenshotUrl`                                                   | The screenshot | The captured frame           |

`selection` holds:

| Field     | Type             | Description                                     |
| --------- | ---------------- | ----------------------------------------------- |
| `startMs` | `number`         | Start of the marked time, in milliseconds       |
| `endMs`   | `number \| null` | End of a range, or `null` for an instant        |
| `point`   | `object \| null` | `{ x, y }`, a point on the frame                |
| `area`    | `object \| null` | `{ x, y, width, height }`, an area on the frame |

At most one of `point` and `area` is set. Both are `null` when the Reviewer marked a time only. Coordinates are normalized from 0 to 1 of the frame: multiply by the Video's `width` and `height` to get pixels.

### Markdown response

When `format=markdown`, the response is a structured markdown document with sections for each feedback item, ready for AI agent consumption. It works with or without the `video` filter.

For a video item, the "Where to look" section reads:

```md
## Where to look

**Video:** Homepage walkthrough v1
**When:** At 00:12.340 (12340 ms)
**Where on the frame:** Point at 42%, 61%
```

A range reads `From 00:41.000 to 00:47.500 (41000 to 47500 ms)` and an area reads `Area from (10%, 20%) to (55%, 70%)`. The **Where on the frame** line is omitted when the Reviewer marked a time only.

A Feedback with a Recording carries one line after its Diagnostics:

```md
**Recording:** 42.3 s, 18 steps. Call `get_feedback` with id `0b6c1f52-3d8e-4a9b-8c7d-1e2f3a4b5c6d` to read its timeline.
```

The number of steps is left out until a request for the single Feedback has read them.

## Get a feedback

```
GET /feedbacks/:id
```

Returns one Feedback of the token's Organization in full, page or Video alike. It is the call that reads a [Recording](/docs/widget/recording).

### Query parameters

| Parameter | Type     | Required | Description                    |
| --------- | -------- | -------- | ------------------------------ |
| `format`  | `string` | No       | `json` (default) or `markdown` |

An `id` that is not a UUID returns `422` with `Invalid feedback ID`. A Feedback that does not exist or belongs to another Organization returns `404` with `Feedback not found`.

### JSON response

The item has the same keys as in [List feedbacks](#list-feedbacks), and its `recording` carries the whole Recording:

```json
{
  "id": "0b6c1f52-3d8e-4a9b-8c7d-1e2f3a4b5c6d",
  "status": "new",
  "comment": "The save button does nothing",
  "videoId": null,
  "pageUrl": "https://myapp.com/settings",
  "selection": null,
  "selector": "#save",
  "clickX": 450,
  "clickY": 320,
  "viewportWidth": 1920,
  "viewportHeight": 1080,
  "browserName": "Chrome",
  "browserVersion": "142",
  "os": "macOS",
  "screenshotUrl": "https://…/shot.png?X-Amz-Expires=3600&…",
  "metadata": { "elementDescription": "button \"Save changes\"" },
  "diagnosticTrail": { "console": [], "network": [] },
  "customMetadata": null,
  "reviewerName": "Sarah",
  "createdAt": "2026-11-04T09:12:33.000Z",
  "recording": {
    "durationMs": 42300,
    "startedAt": 1794400017700,
    "endedAt": 1794400060000,
    "readable": true,
    "steps": [
      {
        "type": "click",
        "timestamp": 1794400047600,
        "offsetMs": -12400,
        "label": "button \"Save changes\"",
        "selector": "form.settings > button.primary",
        "detail": null
      },
      {
        "type": "selection",
        "timestamp": 1794400060000,
        "offsetMs": 0,
        "label": "button \"Save changes\"",
        "selector": "#save",
        "detail": null
      }
    ],
    "url": "https://…/recording?X-Amz-Expires=3600&…"
  }
}
```

`recording` is `null` when the Feedback has no Recording, including one whose Recording has not reached the server yet.

| Field                  | Type             | Description                                                                                               |
| ---------------------- | ---------------- | --------------------------------------------------------------------------------------------------------- |
| `durationMs`           | `number`         | Duration in milliseconds                                                                                  |
| `startedAt`, `endedAt` | `number \| null` | Both ends of the Recording, in epoch milliseconds. `null` when the file cannot be read                    |
| `readable`             | `boolean`        | `false` when the file cannot be read                                                                      |
| `steps`                | `array`          | What the Reviewer did, oldest first, ending with the `selection` step. Empty when the file cannot be read |
| `steps[].type`         | `string`         | `load`, `click`, `input`, `select`, `submit`, `navigation`, `scroll`, `resize` or `selection`             |
| `steps[].timestamp`    | `number`         | Epoch milliseconds                                                                                        |
| `steps[].offsetMs`     | `number`         | Zero or negative: the time before the end of the Recording                                                |
| `steps[].label`        | `string \| null` | The element in words, such as `button "Save changes"`                                                     |
| `steps[].selector`     | `string \| null` | A CSS selector of the element                                                                             |
| `steps[].detail`       | `string \| null` | What the step changed, such as a scroll position. Typed values are never captured                         |
| `url`                  | `string`         | A signed link to the Recording file. It expires one hour after the response, like `screenshotUrl`         |

`diagnosticTrail` is returned unchanged next to `recording`. When the file cannot be read, the response is still `200`, with `readable: false` and no steps.

### Markdown response

With `format=markdown`, the response is the Feedback's document, with the same sections as an item of the listing. When the Feedback has a readable Recording, a **Timeline** section takes the place of **Diagnostics**. It merges the steps with the console logs and network requests in time order, each with its time before the Selection, and ends with the selected element:

```md
## Timeline

- -12.4 s click button "Save changes" (form.settings > button.primary)
- -12.0 s `POST` https://myapp.com/api/settings → 500 (120ms)
- -11.0 s `error` Save failed
- 0.0 s selection button "Save changes" (#save), the element the comment is about
```

A long Timeline keeps the entries closest to the Selection, console errors and failed network responses first. A line above the entries says how many earlier entries were omitted, and another how many console logs and network requests came after the Selection, while the Reviewer wrote the comment. The markdown never carries the link to the Recording file.

The listing's markdown never has a Timeline: only the single Feedback's does.

When the Recording file cannot be read, the document keeps its **Diagnostics** section and adds:

```md
**Recording:** the file could not be read, so this Feedback has no timeline.
```

## List videos

```
GET /videos?project=proj_xxx
```

Lists the Project's Videos that are ready for review, newest first. Videos still uploading are omitted. Use an `id` from this list as the `video` filter of [List feedbacks](#list-feedbacks).

### Query parameters

| Parameter | Type     | Required | Description                  |
| --------- | -------- | -------- | ---------------------------- |
| `project` | `string` | Yes      | Project ID (prefix: `proj_`) |

### Response

```json
{
  "videos": [
    {
      "id": "d4f0a2c1-7e3b-4b7a-9a1e-2c5f8e9d1b23",
      "title": "Homepage walkthrough v1",
      "filename": "homepage-walkthrough.mp4",
      "durationMs": 94200,
      "width": 1920,
      "height": 1080,
      "annotationsOpen": true,
      "openFeedbackCount": 2,
      "createdAt": "2026-11-04T08:55:10.000Z"
    }
  ],
  "count": 1
}
```

| Field               | Description                                             |
| ------------------- | ------------------------------------------------------- |
| `durationMs`        | Duration in milliseconds                                |
| `width`, `height`   | Frame size in pixels                                    |
| `annotationsOpen`   | Whether Reviewers can still leave feedback on the Video |
| `openFeedbackCount` | Feedback with the status `new` or `in_progress`         |

The list is not paginated.

## Update feedback status

```
POST /feedbacks/:id/status
Content-Type: application/json
```

### Body

```json
{
  "status": "resolved"
}
```

### Parameters

| Field    | Type     | Required | Description                                   |
| -------- | -------- | -------- | --------------------------------------------- |
| `status` | `string` | Yes      | `new`, `in_progress`, `resolved`, or `closed` |

### Response

```json
{
  "id": "uuid",
  "status": "resolved",
  "updatedAt": "2025-01-15T11:00:00Z"
}
```

If a GitHub issue is linked, the status change is automatically synced. The call is the same for page and video feedback.

## Rate limits

| Action         | Limit             |
| -------------- | ----------------- |
| List feedbacks | 200 requests/hour |
| Update status  | 50 requests/hour  |

Get a feedback and List videos count against the same read limit as List feedbacks.

## Required scopes

| Endpoint                     | Scope                     |
| ---------------------------- | ------------------------- |
| `GET /feedbacks`             | `feedbacks:read`          |
| `GET /feedbacks/:id`         | `feedbacks:read`          |
| `GET /videos`                | `feedbacks:read`          |
| `POST /feedbacks/:id/status` | `feedbacks:update_status` |
